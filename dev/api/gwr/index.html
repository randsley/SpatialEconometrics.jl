Geographically Weighted Regression

GWR and multiscale GWR: coefficient surfaces rather than single coefficients.

SpatialEconometrics.GWREstimation.AdaptiveBandwidth — Type
AdaptiveBandwidth(k)

A nearest-neighbour bandwidth: each local regression uses its k closest observations, so the radius expands in sparse areas and contracts in dense ones.

The more robust default for irregularly spaced data, since every local fit gets the same number of observations. k must comfortably exceed the number of parameters.

Examples

fit_gwr(X, y, coords; bandwidth = AdaptiveBandwidth(30))
source
SpatialEconometrics.GWREstimation.BandwidthType — Type
BandwidthType

How the GWR neighbourhood around each location is sized. Subtypes: FixedBandwidth and AdaptiveBandwidth.

The bandwidth is the single most consequential GWR choice: too small and the local coefficients chase noise, too large and they flatten towards the global regression.

source
SpatialEconometrics.GWREstimation.BisquareKernel — Type
BisquareKernel()

Bisquare weighting, (1 - (d/h)^2)^2 inside the bandwidth and exactly zero outside.

The default here and the usual GWR choice: the hard cut-off makes each local fit genuinely local and keeps the computation sparse.

See also GaussianKernel, ExponentialKernel.

source
SpatialEconometrics.GWREstimation.ExponentialKernel — Type
ExponentialKernel()

Exponential weighting, exp(-d/h). Decays faster near the origin than GaussianKernel and, like it, has no hard cut-off.

source
SpatialEconometrics.GWREstimation.FixedBandwidth — Type
FixedBandwidth(h)

A constant kernel bandwidth h, in the units of the coordinates, used at every location.

Appropriate when units are spread evenly. Where density varies, a fixed radius means sparse regions contribute few observations to their local fit — sometimes fewer than there are parameters — so AdaptiveBandwidth is usually safer with irregular data.

Examples

fit_gwr(X, y, coords; bandwidth = FixedBandwidth(2.5))
source
SpatialEconometrics.GWREstimation.GWRModel — Type
GWRModel

A fitted geographically weighted regression, returned by fit_gwr. Implements the StatsAPI.RegressionModel interface.

Rather than one coefficient vector, GWR estimates a separate regression at every location, so the headline output is the N x K surface coef_local.

Fields

  • coef_local, se_local: N x K local coefficients and their standard errors, columns ordered as coefnames.
  • coef_global: column means of coef_local, a summary only.
  • y, X, coords, residuals, fitted: the data and the fit. X includes the intercept column that was added for you.
  • local_R2: goodness of fit of each local regression.
  • bandwidth, bandwidth_type, kernel: the neighbourhood actually used.
  • AICc, R2, sigma2: global fit measures.
  • hat_trace: tr(S), the effective number of parameters.
  • coefnames: "(Intercept)" followed by the covariate names.
Warning

The local standard errors are not adjusted for the fact that N regressions were run on overlapping data, so pointwise t-statistics overstate significance. Read the surface as description, and use plot_gwr_coefficients to look at it.

source
SpatialEconometrics.GWREstimation.GaussianKernel — Type
GaussianKernel()

Gaussian weighting, exp(-0.5 (d/h)^2).

Weights decline smoothly and never reach zero, so every observation contributes to every local fit. That makes the coefficient surface smooth but means the "local" regression is never strictly local.

See also BisquareKernel.

source
SpatialEconometrics.GWREstimation.KernelFunction — Type
KernelFunction

Weighting applied to neighbours within a GWR bandwidth. Subtypes: GaussianKernel, BisquareKernel, ExponentialKernel.

source
SpatialEconometrics.GWREstimation.MGWRModel — Type
MGWRModel

A fitted multiscale geographically weighted regression, returned by fit_mgwr.

Differs from GWRModel in carrying bandwidths, one per covariate, instead of a single bandwidth.

Fields

  • coef_local, se_local: N x K local coefficients and standard errors.
  • coef_global: column means of coef_local.
  • y, X, coords, residuals, fitted: the data and the fit.
  • bandwidths: the selected bandwidth per fitted coefficient, aligned with coefnames (intercept first). This is the substantive result — a large value means that relationship is close to constant in space, a small one that it varies locally.
  • kernel, R2, coefnames: as for GWRModel.
  • enp: tr(R_k) for each fitted coefficient, the effective number of parameters that covariate's own bandwidth buys. Aligned with coefnames. This is the quantity that makes two MGWR fits comparable, and the per-covariate counterpart of hat_trace.
  • hat_trace: tr(S) = sum(enp), the effective number of parameters of the whole fit.
  • enp_se: the Monte Carlo standard error of each enp, zero when the degrees of freedom were computed exactly and NaN when they were not computed at all. Under :stochastic it is not decoration: AICc inherits the same noise, so a difference of a few AICc units between two fits may be the estimator rather than the models.
  • df_method: :exact, :stochastic or :none, recording how the degrees of freedom were obtained.
  • AICc, sigma2: penalised by hat_trace, so directly comparable with the same fields on a GWRModel.
  • iterations, converged: state of the back-fitting loop. Check converged before interpreting anything.
Note

enp, hat_trace and AICc are NaN when the degrees-of-freedom accumulator was skipped — see the inference keyword of fit_mgwr — because an MGWR fit carries no usable information criterion without it.

source
SpatialEconometrics.GWREstimation.fit_gwr — Function
fit_gwr(X, y, coords; bandwidth = nothing, kernel = BisquareKernel(), varnames = nothing)

Fit a geographically weighted regression: a separate weighted least squares at every location.

Each local fit weights observations by their distance from the target location, so the result is a coefficient surface rather than a single vector. This describes how a relationship varies over space; it does not model spatial dependence in the error, which is what fit_spatial and fit_spatial_error are for.

Arguments

  • X: N x K covariates, without an intercept — one is added.
  • y: response of length N.
  • coords: N x 2 matrix of locations.

Keywords

  • bandwidth: a FixedBandwidth or AdaptiveBandwidth. nothing (the default) selects an adaptive bandwidth by minimizing corrected AIC, which costs an extra search but is the sensible default.
  • kernel: a KernelFunction.
  • varnames: covariate names; defaults to x1, x2, ....

Returns

A GWRModel.

Examples

m = fit_gwr(X, y, coords; varnames = ["income", "density"])
m.bandwidth
m.coef_local[:, 2]                        # the surface for "income"

fit_gwr(X, y, coords; bandwidth = AdaptiveBandwidth(30), kernel = GaussianKernel())
plot_gwr_coefficients(m, "income")        # needs a Makie backend
Warning

Local standard errors ignore the multiplicity of running N overlapping regressions, so pointwise significance is overstated.

See also fit_mgwr, which lets each covariate have its own bandwidth.

References

Fotheringham, A. S., Brunsdon, C. & Charlton, M. (2002). Geographically Weighted Regression. Wiley.

SpatialEconometrics.GWREstimation.fit_mgwr — Function
fit_mgwr(X, y, coords; kernel = BisquareKernel(), varnames = nothing,
         max_iter = 50, tol = 1e-4)

Fit a multiscale GWR, giving every covariate its own bandwidth.

Standard fit_gwr forces one bandwidth on all relationships, which is a real restriction: some processes genuinely operate at a regional scale and others very locally. MGWR relaxes it by back-fitting, cycling through the covariates and re-selecting each bandwidth with the others held fixed until the coefficients stop moving.

The selected bandwidths are themselves the interesting output — a bandwidth near N says that relationship is effectively global.

Arguments

As fit_gwr: X without an intercept, y, and N x 2 coords.

Keywords

  • kernel: a KernelFunction.
  • varnames: covariate names.
  • max_iter, tol: back-fitting iteration cap and convergence tolerance. Back-fitting runs in two phases: bandwidths are re-selected each sweep until they stop moving, then held fixed while the coefficients converge. The second phase is where the sweeps go – Columbus settles its bandwidths after 5 sweeps and then needs about 100 more – so max_iter has to be generous. Those later sweeps are cheap, since the AICc search is what costs.
  • inference: how to obtain the degrees of freedom, which is what identifies enp, hat_trace and AICc.
    • true (default): exact, by accumulating the smoother operators. Needs K + 1 dense N x N matrices, hence max_inference_n.
    • :stochastic: Hutchinson probing. O(N) in memory, so it has no size gate, and it estimates the whole enp vector rather than just its sum. The estimate is unbiased but random – see enp_se – and se_local stays approximate, because a standard error needs a row norm per observation and no trace estimator provides one.
    • false: skip it. enp, hat_trace and AICc are NaN.
  • max_inference_n: fall back from exact to NaN above this N (default 2000), warning rather than erroring. Pass inference = :stochastic to get degrees of freedom there instead.
  • probes, rng: probe count and random stream for :stochastic (default 200). Seed rng for a reproducible AICc; enp_se falls as 1/sqrt(probes). The default is 200 rather than the 30-50 usually quoted for Hutchinson because enp_se is mildly optimistic at small probe counts: against an exactly solved fixed point its z-scores have standard deviation 1.28 at 50 probes and 1.04 at 200, so nominal 95% intervals cover about 91%. The estimate itself is unbiased at either count – it is the width that is understated, because a quadratic form in Rademacher variables is not Gaussian and its variance is itself estimated from the same few probes.

Returns

An MGWRModel.

Warning

Back-fitting is not guaranteed to converge, and converged now requires both that the bandwidths settled and that the coefficients reached tol. Check m.converged before reading the coefficients; if it is false, raise max_iter or loosen tol. Convergence is slow when the covariates are spatially correlated with each other, because the additive components then compete for the same variation: the contraction factor on Columbus is about 0.94 per sweep.

Examples

m = fit_mgwr(X, y, coords; varnames = ["income", "density"])
m.converged || @warn "back-fitting did not converge"
m.bandwidths               # aligned with m.coefnames, intercept first

References

Fotheringham, A. S., Yang, W. & Kang, W. (2017). Multiscale geographically weighted regression. Annals of the American Association of Geographers, 107(6).

Yu, H., Fotheringham, A. S., Li, Z., Oshan, T., Kang, W. & Wolf, L. J. (2020). Inference in multiscale geographically weighted regression. Geographical Analysis, 52(1) - the degrees-of-freedom accumulator.
