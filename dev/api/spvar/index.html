Spatial Vector Autoregression

API reference for SpVAR. See Spatial VAR for the discussion, and Weight Matrices for order_weights, which builds the W⁽ˡ⁾ this module needs.

Module

SpatialEconometrics.SpVAR — Module
SpVAR

Spatial vector autoregression — Di Giacinto (2010).

fit_star in SpatioTemporalModels traces one variable through space and time. This module does the same for a system of K interdependent variables observed on N locations, which forces a question a univariate model never raises: within a single period, which variable moves first?

The answer is an identifying assumption, not something the data settles, so ordering is a required argument of fit_spvar with no default.

What makes this tractable

Di Giacinto's two structural choices are what keep the model usable:

  1. Spatially structured coefficient blocks (his eq. 7). Each N×N block of each NK×NK coefficient matrix is Σₗ W⁽ˡ⁾Φₗ, a combination of order-l weights matrices. Free parameters per lag fall from (NK)² to NK²(s+1) — linear in N, not quadratic.
  2. Block-triangular C₀ (his eq. 9), not strictly triangular. A strictly triangular C₀ would impose a recursive causal order on the locations as well as the variables — a one-way causal chain through space, which is wrong for spatial problems where interaction is bilateral. Block triangularity keeps the ordering across variables and restores bilateral interaction in space.

Choice 2 has a consequence that does the computational work. Block triangularity gives |C₀| = Πᵣ |A⁽⁰⁾ᵣᵣ|, so the concentrated log-likelihood separates into K unrelated terms, one per equation (his eqs. 22–23), each maximisable on its own. A SpVAR is K spatial autoregressions, not one NK×NK problem.

The asymptotics are not the package's usual ones

Inference here is T → ∞ at fixed N, as the paper states: these are standard structural-VAR asymptotics. Every other panel estimator in this package is consistent as N grows. Bringing a wide, short panel to fit_spvar is a mistake, and fit_spvar says so in its docstring with the measured rates.

References

  • Di Giacinto, V. (2010). On vector autoregressive modeling in space and time. Journal of Geographical Systems, 12(2), 125–154.
  • Anselin, L., & Smirnov, O. (1996). Efficient algorithms for constructing proper higher order spatial lag operators. Journal of Regional Science, 36(1), 67–89.
  • Lütkepohl, H. (2007). New Introduction to Multiple Time Series Analysis. Springer.

The order condition

SpatialEconometrics.SpVAR.OrderConditionResult — Type
OrderConditionResult

Verdict from spvar_order_condition.

Fields

  • satisfied::Bool — whether the order condition holds.
  • n_restrictions::Int — zero restrictions on the structural error covariance, NK(NK−1)/2, since every covariance is nil and every variance free.
  • n_free::Int — free coefficients in C₀.
  • n_min::Int — the smallest N that satisfies the condition at this K and s.
  • homogeneous::Bool — which parameterisation was counted.
  • N, K, s.
Necessary, not sufficient

This is the order condition for identification via zero restrictions (Hamilton 1994, p. 332): it counts equations against unknowns and nothing more. Satisfying it does not establish identification, and a model that satisfies it can still be near-singular. It is a cheap refusal for the cases Di Giacinto names as genuinely under-identified — small N with high spatial order — not a certificate.

source
SpatialEconometrics.SpVAR.spvar_order_condition — Function
spvar_order_condition(N, K, s; homogeneous = true)

Check Di Giacinto's order condition for identification of C₀ — his eqs. (13) and (14) — and return an OrderConditionResult.

The condition compares the NK(NK−1)/2 zero restrictions on the structural error covariance against the free coefficients in C₀. In the spatially heterogeneous parameterisation it reduces to

N ≥ s + (s + K)/K

so for K = 2 it requires N ≥ 3 at s = 1 and N ≥ 4 at s = 2 — the paper's own worked numbers, which the suite pins exactly. The bound decreases in K, because coefficients grow linearly in K while the restrictions grow quadratically.

In the homogeneous parameterisation (his eq. 8) the coefficient count does not scale with N at all, so the condition binds only for very small N.

fit_spvar calls this and refuses rather than returning estimates for an under-identified system.

Estimation

SpatialEconometrics.SpVAR.SpVARModel — Type
SpVARModel

A fitted spatial VAR, from fit_spvar.

Fields

  • rho::Vector{Vector{T}} — rho[k][l] is the own contemporaneous spatial coefficient on W⁽ˡ⁾ in equation k, l = 1,…,s. These are the endogenous terms, the ones the Jacobian exists for.
  • theta::Vector{Vector{T}} — the predetermined coefficients of equation k: the r < k contemporaneous blocks first, then the lag blocks.
  • lambda::Matrix{T} — N×K of structural error variances λ̂ᵢₖ (eq. 21). Location-specific by construction: the paper's Λ is diagonal with free diagonal.
  • means::Matrix{T} — N×K location means removed to absorb the paper's intercept vector μ, in causal order. Kept because spvar_forecast needs them to return levels rather than deviations.
  • C0::Matrix{T}, C::Vector{Matrix{T}} — the assembled NK×NK structural matrices, C[h] for lag h.
  • Wl::Vector{SparseMatrixCSC{T,Int}} — [W⁽⁰⁾ = I, W⁽¹⁾, …, W⁽ˢ⁾].
  • ordering::Vector{Int} — the causal order, as column indices of the Y that was passed in. ordering[1] moves first.
  • varnames::Vector{String} — in causal order.
  • vcov_eq::Vector{Matrix{T}} — per-equation covariance of [rho[k]; theta[k]], from the numerical Hessian of that equation's concentrated log-likelihood. Block diagonal across equations because the likelihood separates (eq. 23).
  • loglik::T — the concentrated log-likelihood, eq. (22).
  • loglik_eq::Vector{T} — its K separable components, eq. (23).
  • residuals::Matrix{T} — N*T_eff × K structural residuals, in causal order.
  • N, K, p, s, T_periods, T_eff.
  • spectral_radius::T, stationary::Bool — of the Kp·N companion matrix of the reduced form, not of any single C_h.
  • converged::Bool, iterations::Int.
  • homogeneous::Bool — always true in this version; see fit_spvar.

SpatialEconometrics.SpVAR.fit_spvar — Function
fit_spvar(Y, W, N, T_per; ordering, p = 1, s = 1, Wl = nothing,
          rho_bounds = (-0.95, 0.95), maxiter = 200, tol = 1e-9,
          varnames = nothing)

Fit Di Giacinto's (2010) structural spatial VAR by full-information maximum likelihood.

Arguments

  • Y: N*T_per × K. Columns are variables; rows follow the package's unit-within-time convention, (t−1)*N + i, as every other panel estimator here takes. The paper's location-within-variable stacking is built internally.
  • W: first-order N×N weights. Higher orders are derived with order_weights_list unless Wl is supplied.
  • ordering: required. A permutation of 1:K (or a vector of names) giving the contemporaneous causal order, first mover first.

Why ordering has no default

Identification of C₀ rests entirely on it. There is no data-driven default and offering one would hide the single assumption the user is making. Reversing it changes the impulse responses — measured, reversing a two-variable ordering moves the peak global outward STIR by a factor reported in docs/AUDIT.md, not by a rounding error.

Spatial order and the log-determinant

Each equation needs log|I − Σₗ ρₗW⁽ˡ⁾|. At s = 1 this is the familiar log|I − ρW|; at s ≥ 2 it is a combination of several weights matrices, and the package's chebyshev_logdet does not apply — it approximates a one-parameter family by construction. Sparse LU is used throughout, which is also what the paper assumes ("moderate" N).

Spatial homogeneity

This version fits the spatially homogeneous specification, the paper's eq. (8): coefficients are common across locations, while the structural error variances λᵢₖ remain location-specific (its eq. 4 keeps Λ's diagonal free). The fully heterogeneous eq. (7), with a separate coefficient per location, is not implemented; spvar_order_condition still counts both so the guard is available either way.

Asymptotics

T → ∞ at fixed N. This is not a large-N estimator, unlike everything else in the package's panel modules. Location-specific intercepts are absorbed by demeaning each location's series over the estimation window, which is algebraically the same as estimating them (Frisch–Waugh) and carries the usual dynamic-panel bias of order 1/T.

See also space_time_stir, spvar_irf, lr_spatial_interaction.

Space-time impulse responses

SpatialEconometrics.SpVAR.spvar_irf — Function
spvar_irf(m::SpVARModel; horizon = 10)

The structural moving-average coefficients Ψ₀,…,Ψ_H of Di Giacinto's eqs. (24)–(26), as a Vector of NK×NK matrices.

Ψ_h[(k−1)N+i, (r−1)N+j] = ∂yᵢₖ,ₜ₊ₕ/∂u_{jrt} — his eq. (28): the response of variable k at location i, h periods on, to a one-unit structural shock to variable r at location j.

Built from the reduced form C̃_h = C₀⁻¹C_h by Ψ̃₀ = I, Ψ̃ᵢ = Σ_{h} Ψ̃ᵢ₋ₕ C̃_h, then Ψ_h = Ψ̃_h C₀⁻¹.

Summed over all horizons this converges to (C₀ − Σ_h C_h)⁻¹, the long-run multiplier, which is the identity the suite pins it against.

For anything but a handful of locations the raw Ψ_h is unreadable — NK×NK numbers per horizon. space_time_stir is the summary designed for that.

source
SpatialEconometrics.SpVAR.STIRResult — Type
STIRResult

Space-time impulse responses, from space_time_stir.

Fields

  • outward::Array{T,4} — [h+1, l+1, k, r], the global outward STIR of eq. (31): the average effect, h periods on, on variable k at the order-l neighbours of a unit shock to variable r.
  • inward::Array{T,4} — the global inward STIR of eq. (32): the average effect on variable k at a location of shocks to variable r at its order-l neighbours.
  • local_outward, local_inward::Array{T,5} — [h+1, l+1, k, r, i], the per-location eqs. (29)–(30). Empty unless store_local = true.
  • horizon::Int, orders::UnitRange{Int} — 0:s.
  • varnames::Vector{String} — in causal order.
  • N, K, cumulative::Bool.

Reading it

Order l = 0 uses W⁽⁰⁾ = I, so it is the own-location response; the spillovers are l ≥ 1, indexed by graph distance. Outward and inward differ by a transpose of the response block and coincide only in special cases — see space_time_stir.

source
SpatialEconometrics.SpVAR.space_time_stir — Function
space_time_stir(m::SpVARModel; horizon = 10, cumulative = false,
                store_local = false)

Di Giacinto's space-time impulse response function — his eqs. (29)–(32).

The raw Ψ_h of spvar_irf holds (NK)² numbers per horizon, which no one can read. The STIR collapses the spatial dimension by averaging over spatial order instead of over locations, so what survives is a response indexed by time since the shock and distance from it — which is the question a spatial VAR is usually fitted to answer.

Two directions, and they are not the same quantity:

  • outward, eq. (29)/(31): ζ⁽ʰˡ⁾ₖᵣ(i) = Σⱼ w⁽ˡ⁾ᵢⱼ Ψ⁽ʰ⁾ₖᵣ(j,i) — shock at i, effect on i's order-l neighbours. "Where does my shock go?"
  • inward, eq. (30)/(32): ξ⁽ʰˡ⁾ₖᵣ(i) = Σⱼ w⁽ˡ⁾ᵢⱼ Ψ⁽ʰ⁾ₖᵣ(i,j) — shocks at the neighbours, effect at i. "Whose shocks reach me?"

They differ by transposing the response block, so globally they are tr(W⁽ˡ⁾Ψ)/N against Σᵢⱼ W⁽ˡ⁾ᵢⱼΨᵢⱼ/N. These coincide exactly when the response block is symmetric, and differ otherwise — a unit that sends more than it receives is precisely what an asymmetric response captures.

Row standardisation alone makes them differ

The obvious guess is that outward and inward coincide whenever K = 1, since the blocks are then polynomials in the weights and commute. That is true only if W⁽ˡ⁾ is symmetric, and row-standardising an irregular graph is enough to break it: on a 14-unit path the row-standardised W⁽¹⁾ has max|W − Wᵀ| = 0.5, and the two STIRs differ by 1.345e-02 (examples/29_spvar.jl, section 4).

Measured on the same design with symmetry preserved, they agree to machine precision: 2.776e-17 with the spectrally standardised path weights, whose max|W − Wᵀ| is exactly zero, and 0.0e+00 on a ring, where every unit has two neighbours so even row standardisation keeps W⁽¹⁾ symmetric.

If you want the two directions to coincide on an irregular graph, spectral_standardize bounds the spectrum without touching symmetry. Note that leaving the weights raw is not an alternative: a binary path has eigenvalues near 2, so a model that is stationary under standardised weights is explosive under raw ones.

So the gap is not only a multivariate effect. Under row standardisation, a unit with fewer neighbours sends and receives on different scales, and the outward/inward split reports that.

cumulative = true accumulates over horizons, so entry h is the total effect through period h.

With store_local = true the per-location eqs. (29)–(30) are kept as well, at N times the memory.

Forecasting

SpatialEconometrics.SpVAR.spvar_forecast — Function
spvar_forecast(m::SpVARModel, h; y_history)

h-step dynamic forecasts from the reduced form, his eq. (12): E[yₜ | ℱₜ₋₁] = Σ_h C̃_h yₜ₋ₕ, with forecasts substituted for realisations once the data runs out.

y_history is required and must be N*p × K in the same layout as the Y passed to fit_spvar — the last p periods, oldest first, and in the original column order, not the causal one. The model does not retain the sample, so omitting it is an error rather than a default.

Returns N*h × K in that same layout and in levels: the location-specific means absorbed during fitting are added back, which is what m.means is kept for.

SpatialEconometrics.SpVAR.fit_nested_panel_var — Function
fit_nested_panel_var(Y, N, T_per; ordering, p = 1, homogeneous = true,
                     varnames = nothing)

Fit Di Giacinto's nested panel VAR, his eqs. (15)–(18): the SpVAR with all spatial interaction coefficients zero, so every N×N block of every C_h is diagonal and the system decomposes into one structural recursive VAR per location.

Because M₀,ᵢ is unit lower triangular its determinant is 1, so there is no Jacobian and no spatial parameter — this is ordinary least squares (or iterated GLS, with the location-specific variances the paper's Λ allows) equation by equation.

Di Giacinto's point about this model is structural, not computational: block triangularity of C₀ preserves this model's identification even when the SpVAR itself is under-identified, which is his stated reason for preferring it to a strictly triangular C₀. That is what makes lr_spatial_interaction well posed.

`homogeneous = true` is the comparable case

The paper writes eqs. (15)–(18) with location-indexed coefficients φᵢₖᵣ, matching its spatially heterogeneous SpVAR. fit_spvar fits the homogeneous specification (eq. 8), whose zero-spatial restriction gives a panel VAR with coefficients common across locations. The heterogeneous version has more parameters, not fewer, so it is not nested in the homogeneous SpVAR and must not be used for a likelihood-ratio test against it. homogeneous = true, the default, is the one that nests.

This is written independently of fit_spvar — no shared solver — precisely so that fit_spvar(…, s = 0) can be checked against it.

source
SpatialEconometrics.SpVAR.lr_spatial_interaction — Function
lr_spatial_interaction(m::SpVARModel, Y, W)

Likelihood-ratio test of no spatial interaction: SpVAR(p, s) against SpVAR(p, 0), the nested panel VAR of eqs. (15)–(18).

Returns a NamedTuple (stat, df, p_value, loglik_full, loglik_restricted, s).

Y and W must be the data m was fitted to; the model does not retain them, and passing something else gives a meaningless answer rather than an error, so this is checked for shape only. The restricted fit re-uses m's ordering, p and variable names.

Setting s = 0 makes every W⁽ˡ⁾ block collapse to W⁽⁰⁾ = I, so A⁽⁰⁾ₖₖ = I, the Jacobian vanishes and the model is the nested panel VAR in homogeneous form. The two hypotheses are therefore nested by construction rather than by argument, and the degrees of freedom are counted from the actual parameter vectors, not from a formula.

Asymptotics again

The χ² reference distribution is justified by T → ∞ at fixed N. The suite measures this statistic's size, and that measurement — not the asymptotic claim — is what docs/AUDIT.md reports.
